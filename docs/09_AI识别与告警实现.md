# AI 识别、告警与自动跟踪实现

> **最后更新**：2026-10-21

本文描述当前代码中的 AI 识别链路、事件广播、证据落盘和自动跟踪控制边界。

## 当前链路

```text
RTSP / MediaMTX
  -> backend/workers_ai.py
  -> YOLO / TensorRT 主目标检测（person/head/helmet）
  -> 共享同帧的独立武器检测（guns/knife，低频巡检 + 命中后逐帧复核）
  -> backend/pose_detection.py（人体关键点 + 时序姿态事件）
  -> backend/weather_detection.py（正常/雨/雪/沙尘，低频分类 + 多次投票）
  -> target_manager.py / stranger_policy.py
  -> auto_track_service.py / guard_mission_service.py
  -> control_service.py / control_arbiter.py
  -> ws_event_broadcaster.py + evidence 落盘
```

AI Worker 从 `AI_RTSP_URL` 拉流，按配置进行跳帧、超时保护和推理。普通巡检、自动跟踪、驱离模式都会消费 AI 结果，但控制权必须经过 `ControlArbiter` 和 `SafetySupervisor`。

疑似破坏动作仍要求同一人的双肩、双腕同时可靠可见，双腕明确高于自然垂手的腰线。
候选窗口内至少四个有效采样，单手至少两个显著转向；允许另一手扶持，不要求双手同步或同幅度。
腰线附近摆臂、合掌拍手、双臂向两侧伸展，以及双前臂严重朝向镜头、投影过短的帧不累计动作。
肘部只在清晰可见时用于排除伸展和投影过短，不新增肘部必须可见的条件。短暂漏点保留已观察进度，
但漏点期间的时长、位移和转向不计入证据；采样间隔超过0.5秒重新开始。
默认有效观察时间0.8秒、位移幅度0.15及30秒事件冷却保持不变；动作窗口延长至2.4秒以容纳正常速度的往复。
这仍是全画面的姿态动作候选，不证明与围栏接触或实际损坏。低频或严重遮挡画面可能漏检。

倒地在全画面确认后立即抓拍并写入证据库；持续蹲伏、徘徊也使用全画面，

蹲伏姿态中断后重新计时。跳过推理的帧不参与缺失判断。连续行为保留报警冷却，
离开后再次出现或重新蹲伏视为新的行为，重新达到阈值即可报警。

### 围栏破坏识别

地图上的围栏线段用于选择云台观察方向，姿态动作在全画面独立判断，
不依赖人员脚下投影、机器人到人员的距离或围栏结构变化。
`FenceDetectionService` 的旧结构复核字段仅为客户端兼容保留，当前不产生结构确认事件。

疑似破坏动作要求同一跟踪人员的双肩、双腕同时有效可见，两只手都位于腰线或更高处。
髋部可见时使用髋线确定腰部高度；半身画面缺少髋部时，用1.5倍肩宽估计躯干尺度及腰线。
手部活动使用随肩部方向旋转、按躯干尺度归一化的相对坐标，减少整体平移、转动和缩放的影响。
允许双手幅度、节奏不同，也允许一手扶持、另一手操作；仅有一只手可见不能触发。

至少3次有效采样、有效观察时长达到 `POSE_CHEST_MOTION_SECONDS`，并存在至少两次
有效位置变化及达到 `POSE_CHEST_MOTION_SPAN` 的活动幅度，才产生 `POSE_DAMAGE_SUSPECTED`。
两项配置仍保留原值0.8秒和0.15，没有同时下调持续时长和动作幅度。
这里的数值是软件规则参数，不是现场动作时长或实测识别率。

双腕短暂漏点或人员短暂丢失时，可保留不超过0.5秒间隔的历史进度；
漏检期间不产生动作候选，不累计有效时长，也不将遮挡前后的位置跳变计为活动幅度。
超过间隔、任一手下降至腰线以下、明显关键点跳变或关闭动作开关时清除相应历史。
手部静止、微小抖动和一次位置调整不满足动作条件，单次短促动作也不能绕过观察时长。

告警仍称“疑似破坏动作”，不将骨架运动直接视为实际围栏损坏。
软件测试覆盖腰部动作、非同步双手、单腕缺失、短暂漏检、持续时间、
整体平移/旋转/缩放、不同人员隔离及关闭再开启。真实视频的误报和漏报需要另行记录。

武器支路不参与人员自动跟踪或底盘控制。开启围栏检测后按 `WEAPON_FRAME_SKIP` 运行；
一旦检测到枪械或刀具，先检查武器框是否位于外扩后的人员框附近；无人关联候选
只有达到 `WEAPON_UNATTENDED_CONFIDENCE_THRESHOLD` 才保留。通过语义过滤后，
只有同类别检测框连续达到 `WEAPON_STABLE_HITS`，且相邻框 IoU 不低于
`WEAPON_CONFIRM_IOU_THRESHOLD`，才生成 `E_AI_GUNS` 或 `E_AI_KNIFE` 紧急告警
和证据抓拍。未通过语义过滤的候选不会进入前端叠层。

天气支路复用同一可见光帧，不新增 RTSP 连接，也不产生检测框。当前基线 ViT
原始类别中包含 `rain`、`snow` 和 `sandstorm`；其余原始类别以及低置信度结果
统一映射为 `normal`。结果通过 `AI_STATUS.weather` 和
`GET /api/v1/weather/status` 输出。当前状态中的 `radar_fused=false` 表示这一版尚未
把雷达回波质量加入天气决策，不能把该字段解释为视觉雷达融合已经完成。

## 控制安全边界

控制优先级为：

```text
E-STOP > 遥控器/外部接管 > Web 手动 > 导航 > AutoTrack / GuardMission
```

自动跟踪和驱离模式都不能绕过急停、手动接管、连接状态保护和命令限流。导航联动开启时，导航任务可以启用自动跟踪，但恢复导航前必须由 `nav_auto_track_coordinator.py` 判断任务、场景和定位状态仍然有效。

自动跟踪启用云台协同时，控制顺序如下：

```text
目标框水平偏差
  -> 根据当前变焦和水平视场角换算画面角误差
  -> 修正 Z2-Mini 相对 yaw，使目标保持在画面中心
  -> 相机相对 yaw + 画面角误差 = 目标相对机身方位
  -> 方位超出死区：机器狗只原地转向（速度随角度缩小）
  -> 方位进入死区且距离足够：机器狗前进跟随
```

云台状态读取或控制失败时会立即停止底盘，不会退回“只看目标框中心便直接前进”的
旧逻辑。这样即使相机朝向机器狗侧方，机身也会先转向相机所看的目标方向。进入
跟踪后若人为转动云台或云台发生漂移，系统会再次停车并进入机身对齐；稳定对齐后
云台保持 `head_follow` 朝向机身正前方，后续只旋转机器狗跟踪目标。

## 告警时间日志

每条告警在 `logs/alerts.log` 写入独立记录，并把时间字段保存到证据数据库的 `timing` 字段。
`generated` 记录告警生成，`displayed` 记录首个已接收的可见页面呈现回执，两者按 `evidence_id` 关联。
日志采用 JSON 内容，UTC 时间精确到毫秒，跟随现有日志轮转和保留策略。

- `event_started_at`：后端观察到事件起点。人员及刀枪使用后端帧接收时间；姿态使用连续观察窗口起点。
- `eligible_at`：延迟起算时间。徘徊和蹲伏分别为观察起点加配置阈值，其余姿态从观察窗口起点计。
- `generated_at` / `generation_delay_ms`：进入告警服务的时间，以及距起算时间的毫秒数（包括此前抓拍耗时）。
- `displayed_at` / `display_delay_ms`：可见卡片经两次浏览器动画帧后的呈现近似时间及延迟。
- `clock_uncertainty_ms`：浏览器校时往返耗时的一半加时间量化误差；延迟不自动标记合同验收通过。
- `display_ack_at`：服务器收到呈现回执的时间，独立于呈现时刻。

告警卡片不新增时间字段。页面未呈现或回执失败时保留 `awaiting_visible_page_receipt`，不填零延迟。
无可用事件起点的告警标记 `event_start_unavailable`，只记录已知时间。
后端帧接收时刻不包含摄像头采集到解码前的传输耗时；该段和物理事件起点仍用现场录像核对。
浏览器呈现时间是经过校时的近似观测，不能替代显示器实际曝光测量。
