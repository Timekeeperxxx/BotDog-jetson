# AI 识别、告警与自动跟踪实现

> **最后更新**：2026-08-08

本文描述当前代码中的 AI 识别链路、事件广播、证据落盘和自动跟踪控制边界。

## 当前链路

```text
RTSP / MediaMTX
  -> backend/workers_ai.py
  -> YOLO / TensorRT 主目标检测（person/head/helmet）
  -> 共享同帧的独立武器检测（guns/knife，低频巡检 + 命中后逐帧复核）
  -> backend/pose_detection.py（人体关键点 + 时序姿态事件）
  -> backend/weather_detection.py（正常/雨/雪/沙尘，低频分类 + 多次投票）
  -> target_manager.py / stranger_policy.py
  -> auto_track_service.py / guard_mission_service.py
  -> control_service.py / control_arbiter.py
  -> ws_event_broadcaster.py + evidence 落盘
```

AI Worker 从 `AI_RTSP_URL` 拉流，按配置进行跳帧、超时保护和推理。普通巡检、自动跟踪、驱离模式都会消费 AI 结果，但控制权必须经过 `ControlArbiter` 和 `SafetySupervisor`。

| 模块 | 职责 |
|------|------|
| `backend/workers_ai.py` | 拉流、推理、目标检测、事件生成 |
| `backend/pose_detection.py` | COCO 17 点姿态推理、轻量轨迹和多帧姿态事件 |
| `backend/weather_detection.py` | 可见光天气分类、四类映射和时序投票 |
| `backend/target_manager.py` | 跟踪目标选择、保持、切换 |
| `backend/stranger_policy.py` | 已知/陌生目标策略 |
| `backend/auto_track_service.py` | 自动跟踪状态机和跟踪命令 |
| `backend/follow_decision_engine.py` | 根据目标框计算前进/转向动作 |
| `backend/gimbal_follow_controller.py` | 融合云台 yaw、画面偏差和变焦倍率，计算目标相对机身方位 |
| `backend/guard_mission_service.py` | 视觉驱离模式和黄色区域入侵判定 |
| `backend/services_evidence.py` | 证据查询与删除 |
| `backend/api/routes/auto_track.py` | 自动跟踪 HTTP 控制接口 |
| `backend/api/routes/evidence.py` | 证据接口 |
| `backend/api/routes/recording.py` | 录像接口 |

## 关键配置

| 配置 | 当前含义 |
|------|----------|
| `AI_ENABLED` | 是否启用 AI Worker |
| `AI_RTSP_URL` | AI 拉流地址，通常指向 MediaMTX |
| `AI_RTSP_FALLBACK_URLS` | 备用 RTSP 地址，逗号分隔 |
| `AI_MODEL_PATH` | 模型路径，默认 `models/helmet.engine` |
| `AI_TARGET_CLASSES` | 目标类别，默认 `person/head/helmet` |
| `AI_FRAME_PROCESS_TIMEOUT_SECONDS` | 单帧处理超时保护 |
| `AI_CONTINUOUS_DETECTION_ENABLED` | 无任务时持续运行只读视觉分析，不启用运动控制 |
| `AI_PASSIVE_SESSION_DETECTION_ENABLED` | 普通巡检是否启用被动告警 |
| `WEAPON_ENABLED` | 是否启用独立枪械/刀具检测支路 |
| `WEAPON_MODEL_PATH` | 武器检测 TensorRT Engine 路径 |
| `WEAPON_FRAME_SKIP` | 常态武器检测跳帧数，默认每 3 帧运行一次 |
| `WEAPON_ACTIVE_SECONDS` | 首次命中后保持逐帧复核的时长 |
| `WEAPON_STABLE_HITS` | 武器告警所需连续确认帧数 |
| `WEAPON_CONFIRM_IOU_THRESHOLD` | 连续武器框被视为同一目标所需的最小 IoU |
| `WEAPON_REQUIRE_PERSON_ASSOCIATION` | 普通武器候选是否必须与人员框关联 |
| `WEAPON_PERSON_EXPAND_RATIO` | 判断武器与人员关联时人员框的外扩比例 |
| `WEAPON_UNATTENDED_CONFIDENCE_THRESHOLD` | 无关联人员时仍保留武器候选所需的最低置信度 |
| `WEAPON_ALERT_COOLDOWN_SECONDS` | 同类武器重复告警冷却时间 |
| `WEATHER_ENABLED` | 是否启用正常/雨/雪/沙尘分类支路 |
| `WEATHER_MODEL_PATH` | 本地 Hugging Face 天气模型目录 |
| `WEATHER_INTERVAL_SECONDS` | 天气推理采样间隔，默认 3 秒 |
| `WEATHER_CONFIDENCE_THRESHOLD` | 雨、雪、沙尘生效的最低单帧置信度 |
| `WEATHER_SMOOTHING_WINDOW` / `WEATHER_STABLE_VOTES` | 防止天气结果抖动的窗口和票数 |
| `POSE_ENABLED` | 是否启用人体姿态检测支路 |
| `POSE_MODEL_PATH` | 姿态 TensorRT Engine 路径 |
| `POSE_STABLE_HITS` | 姿态事件所需连续确认帧数 |
| `POSE_CROUCH_SECONDS` | 重点区持续蹲伏告警时间 |
| `POSE_LOITER_SECONDS` | 重点区持续停留告警时间 |
| `AUTO_TRACK_ENABLED` | 启动时自动跟踪默认状态，通常由前端开关控制 |
| `AUTO_TRACK_VX` / `AUTO_TRACK_VYAW` | 自动跟踪线速度与角速度 |
| `AUTO_TRACK_GIMBAL_ENABLED` | 是否启用 Z2-Mini 视线与机身协同跟踪 |
| `AUTO_TRACK_GIMBAL_BODY_DEADBAND_DEG` | 机身允许开始前进的目标方位死区 |
| `AUTO_TRACK_GIMBAL_FORWARD_DEADBAND_DEG` | 初始对准时相机相对机身正前方的严格容差 |
| `AUTO_TRACK_GIMBAL_REALIGN_FRAMES` | 跟踪时相机超过外圈阈值后重新对准所需的连续确认帧数 |
| `AUTO_TRACK_GIMBAL_SERVO_GAIN` | 云台根据画面偏差修正 yaw 的比例 |
| `SNAPSHOT_DIR` | 证据图片目录 |
| `RECORDING_DIR` | 录像目录 |

完整配置以 `backend/config.py` 和 [07_配置项矩阵.md](07_配置项矩阵.md) 为准。

## WebSocket 事件

前端通过 `WS /ws/event` 接收 AI、自动跟踪、驱离、告警和证据相关事件。主要消费方为：

- `frontend/src/hooks/useEventWebSocket.ts`
- `frontend/src/hooks/useAutoTrack.ts`
- `frontend/src/hooks/useEvidence.ts`
- `frontend/src/hooks/useGuardMissionControl.ts`

`POSE_OVERLAY` 携带主模型的 `person/head/helmet`、武器模型的 `guns/knife`
检测框、人体关键点、
粗粒度姿态和重点区停留时间。当前姿态事件包括：

- `POSE_CLIMBING_SUSPECTED`
- `POSE_LYING`
- `POSE_CROUCHING`
- `POSE_LOITERING`

复杂行为不会按单帧直接告警。姿态分类至少需要
`POSE_MIN_VISIBLE_KEYPOINTS` 个可信关键点，并经过连续帧和冷却时间约束。攀爬、
倒地在全画面确认后立即抓拍并写入证据库；持续蹲伏、徘徊仍要求位于重点区。

武器支路不参与人员自动跟踪或底盘控制。巡逻时按 `WEAPON_FRAME_SKIP` 低频运行；
一旦检测到枪械或刀具，先检查武器框是否位于外扩后的人员框附近；无人关联候选
只有达到 `WEAPON_UNATTENDED_CONFIDENCE_THRESHOLD` 才保留。通过语义过滤后，
只有同类别检测框连续达到 `WEAPON_STABLE_HITS`，且相邻框 IoU 不低于
`WEAPON_CONFIRM_IOU_THRESHOLD`，才生成 `E_AI_GUNS` 或 `E_AI_KNIFE` 紧急告警
和证据抓拍。未通过语义过滤的候选不会进入前端叠层。

天气支路复用同一可见光帧，不新增 RTSP 连接，也不产生检测框。当前基线 ViT
原始类别中包含 `rain`、`snow` 和 `sandstorm`；其余原始类别以及低置信度结果
统一映射为 `normal`。结果通过 `AI_STATUS.weather` 和
`GET /api/v1/weather/status` 输出。当前状态中的 `radar_fused=false` 表示这一版尚未
把雷达回波质量加入天气决策，不能把该字段解释为视觉雷达融合已经完成。

## 证据与录像

- AI 或人工抓拍会写入 `data/snapshots`，并生成数据库证据记录。
- 录像接口通过 FFmpeg 从 `AI_RTSP_URL` 录制 MP4，保存到 `RECORDING_DIR`。
- 前端主控台和管理后台都可以查看证据记录；删除操作走后端接口并写审计日志。

## 控制安全边界

控制优先级为：

```text
E-STOP > 遥控器/外部接管 > Web 手动 > 导航 > AutoTrack / GuardMission
```

自动跟踪和驱离模式都不能绕过急停、手动接管、连接状态保护和命令限流。导航联动开启时，导航任务可以启用自动跟踪，但恢复导航前必须由 `nav_auto_track_coordinator.py` 判断任务、场景和定位状态仍然有效。

自动跟踪启用云台协同时，控制顺序如下：

```text
目标框水平偏差
  -> 根据当前变焦和水平视场角换算画面角误差
  -> 修正 Z2-Mini 相对 yaw，使目标保持在画面中心
  -> 相机相对 yaw + 画面角误差 = 目标相对机身方位
  -> 方位超出死区：机器狗只原地转向（速度随角度缩小）
  -> 方位进入死区且距离足够：机器狗前进跟随
```

云台状态读取或控制失败时会立即停止底盘，不会退回“只看目标框中心便直接前进”的
旧逻辑。这样即使相机朝向机器狗侧方，机身也会先转向相机所看的目标方向。进入
跟踪后若人为转动云台或云台发生漂移，系统会再次停车并进入机身对齐；稳定对齐后
云台保持 `head_follow` 朝向机身正前方，后续只旋转机器狗跟踪目标。
