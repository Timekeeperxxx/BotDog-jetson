# BotDog 当前实际导航功能测试用例

## 1. 测试范围

本文只测试当前代码已经接通的实际链路：

```text
导航巡逻页面
  -> BotDog /api/v1/nav/*
  -> ROS2 Navigation
  -> /cmd_vel_safe
  -> 本机 UDP 127.0.0.1:52345
  -> BotDog UnitreeB2Adapter
  -> B2 机器狗
```

包括场景点云、导航点、重定位、单点导航、多点任务、状态与路径回传、动态避障、软急停、建图和导航/AI 跟踪联动。

## 2. 当前实际配置

| 项目 | 当前实现 |
|---|---|
| 场景目录 | `/home/jetson/Projects/Maps` |
| 场景命名 | 必须匹配 `^Scene\d+_` |
| 必需场景文件 | `map.pcd`、`ground.pcd` |
| 可选场景文件 | `*footprint_fill.pcd` |
| PCD 格式 | `DATA ascii` 或 `DATA binary` |
| 地图坐标系 | `map` |
| 机器人坐标系 | `base_footprint` |
| 初始位姿 | `/initialpose`，连续发布 20 次，间隔 0.2 s |
| 单点位置 | `/clicked_point`，每个新目标可靠发布 1 次，并携带保存的同层 ground z |
| 单点朝向 | `goal_yaw`，`std_msgs/Float64`，单位 rad |
| 导航开关 | `/nav_start`，`std_msgs/Bool` |
| 任务开关 | `/nav_task_start`，`std_msgs/Bool` |
| 导航状态 | `/nav_status`，`std_msgs/String` JSON |
| 全局路径 | `/global_path` |
| 执行路径 | `/scan/execution_path` |
| 安全速度 | `/cmd_vel_safe` |
| BotDog 速度入口 | UDP `127.0.0.1:52345`，超时 0.5 s 自动发零速度 |
| B2 最大速度 | `x=0.25 m/s`、`y=0.08 m/s`、`yaw=0.30 rad/s` |
| 到点阈值 | XY ≤ 0.12 m、Z ≤ 1.0 m、最终 yaw ≤ 0.10 rad |
| 导航目标超时 | 当前为 `0`，即不自动超时 |
| 动态避障输入 | `/grid_map/occupancy_inflate` |
| 动态避障停车距离 | 1.20 m |
| 动态避障重规划 | 障碍持续 2.0 s 后发布 `/nav/replan_request=true` |
| 障碍点云超时 | 1.5 s，超时输出零速度 |

### 必须保持的单写入架构

`NAV_ENABLE_ROBOT_CONTROL=false` 是当前正确配置，不要为了真机测试改成 `true`。

Navigation 只输出 `/cmd_vel_safe`，`cmd_vel_ros2_udp_sender.py` 将速度发给 BotDog 的本机 UDP 接收器，最终只有 BotDog `UnitreeB2Adapter` 写入 B2。将 `NAV_ENABLE_ROBOT_CONTROL` 改成 `true` 会增加另一个底盘写入者，可能与 BotDog 手动控制争抢。

## 3. 当前未完整实现的项目

以下内容不应按“已完成功能”验收：

- 页面“添加障碍物”按钮目前只切换按钮状态并写前端日志，没有地图标记、保存或 ROS2 topic 发布逻辑。真实动态避障输入来自雷达 `/grid_map/occupancy_inflate`。
- 任务编辑器可以保存 `posture_control`，后端也会写入 `current_task.json`，但当前 `waypoint_navigator_from_json.py` 只加载 `navigate_waypoint`，不会执行站立或蹲下。
- “导航急停”是软件软停，不是实体急停。它会归零速度并保留定位进程，真机测试仍必须有人控制实体急停。

## 4. 测试前准备

1. 使用 `admin` 账号完成全套测试。`operator` 可以创建和导航，但删除场景、删除导航点需要 `admin`。
2. 准备一个 `SceneN_名称` 场景，至少包含可读取的 `map.pcd` 和 `ground.pcd`。
3. 首次联调先把机器狗架空或关闭电机输出，确认 topic、路径、状态和软急停正确后再落地。
4. 真机落地测试必须清场，并安排一人始终控制实体急停。
5. 确认后端使用 `CONTROL_ADAPTER_TYPE=unitree_b2`，且 Unitree 适配器状态为 ready。

持续观察以下内容：

```bash
ros2 topic echo /initialpose
ros2 topic echo /clicked_point
ros2 topic echo /goal_yaw
ros2 topic echo /nav_start
ros2 topic echo /nav_task_start
ros2 topic echo /nav_status

```

检查速度单写入链路：

```bash

pgrep -af cmd_vel_ros2_udp_sender.py
```

预期只有 BotDog 后端监听 `127.0.0.1:52345`，ROS2 sender 订阅 `/cmd_vel_safe`，没有第二个直接控制 B2 的 Navigation bridge。

## 6. 场景、点云与导航点用例

### ACT-NAV-001 场景扫描与选择

- 优先级：P0
- 前置条件：`MAPS` 下存在一个完整场景和一个缺少 PCD 的场景。
- 操作：进入“BotDog 导航巡逻”，打开场景抽屉，刷新并选择完整场景。
- 预期：只列出名称匹配 `SceneN_` 的目录；完整场景可选择；选择后生成 `data/nav_runtime/current_scene.json`，包含 `scene_id/scene_dir/map_pcd/ground_pcd/planground_pcd`；清理旧 `current_task.json`；定位状态变为等待重新定位。
- 异常检查：缺少 `map.pcd` 或 `ground.pcd` 时选择接口返回 400，不能成为当前场景。

### ACT-NAV-002 点云显示

- 优先级：P1
- 操作：选择场景，分别开关 `map`、`ground`、`footprint` 图层；旋转、缩放点云；查看场景信息。
- 预期：`map.pcd` 显示为 wall 图层，`ground.pcd` 显示为 ground 图层；`footprint_fill` 缺失时不影响场景选择；页面显示 frame、点数、字段、DATA 类型和边界；ASCII、binary PCD 均能读取；不支持或损坏的 PCD 显示错误，不生成伪造点云。

### ACT-NAV-003 创建导航点

- 优先级：P0
- 账号：admin 或 operator
- 操作：点击“添加导航点”，在 3D 蓝色 ground 上按住并拖动确定 yaw，输入“测试点A”，刷新页面。
- 预期：创建 `wp_*` ID；`frame_id=map`；XY、yaw 与标记一致；Z 使用 ground 局部平面吸附结果；数据保存在 `data/nav_waypoints`；刷新后仍存在。
- 校验：空名不保存；同一场景重名被前端拒绝；落点距离 ground 超过 1.0 m 时后端拒绝；ground 拟合使用最多 24 个邻点。

### ACT-NAV-004 删除导航点与场景

- 优先级：P1
- 账号：admin
- 操作：删除一个导航点；再删除测试场景并确认警告框。
- 预期：导航点从 JSON 和页面消失；删除场景时同时删除场景目录、关联导航点、重定位记录、任务和指向该场景的运行时 JSON。
- 权限检查：operator 删除导航点或场景时后端返回 403。

## 7. 重定位与导航用例

### ACT-NAV-005 重启导航定位

- 优先级：P0
- 操作：选择完整场景，点击“重启导航定位”。
- 预期：先取消待恢复的自动跟踪导航，解除 cmd_vel 急停、状态机急停和 E-STOP 控制权；释放导航控制权；清理 `current_task.json`；导航状态变为 idle；旧导航实例被清理后只启动一套新实例。
- 进程预期：Livox、relocation、global planner、SCAN planner、SCAN controller、TF pose、dynamic avoidance、waypoint progress monitor、waypoint navigator 各只有一个实例，并生成对应 PID 文件。

### ACT-NAV-006 initialpose 就绪检查

- 优先级：P0
- 操作：等待页面自动进入“现在标记重定位点”。
- 预期：本轮 `restart_navigation_localization.log` 已出现等待 initialpose 的标记；`relocation.pid` 对应进程仍存活；后端 `/initialpose` publisher 已进入 ROS graph；`/initialpose` 至少有一个订阅者。任一条件失败时页面不得进入标点状态。

### ACT-NAV-007 设置初始位姿

- 优先级：P0
- 操作：在真实机器狗位置的 3D ground 上按住并拖动朝向。
- 预期：位姿先按 ground 吸附并保存到 `data/nav_localization`；后端等待订阅者后向 `/initialpose` 连续发布 20 次，间隔 0.2 s；消息为 `PoseWithCovarianceStamped`，frame 为 `map`；页面状态先为 initializing。
- 最终预期：`map -> base_footprint` TF 恢复；global planner 完成静态图；SCAN TF ready；`navigation_ready.json` 的 stage 变为 `running`；页面显示“导航和任务可用”。

### ACT-NAV-008 未定位禁止导航

- 优先级：P0
- 操作：让 TF 不存在或超过 `ROS_NAV_TF_MAX_AGE_SECONDS=3.0`，然后执行单点导航和任务。
- 预期：后端因没有新鲜 `robot_pose` 或定位状态不是 `ok` 而拒绝请求；不启动速度 sender，不获取 NAVIGATION 控制权，不发布新目标。

### ACT-NAV-009 雷达健康检查

- 优先级：P0
- 操作：点击“检查雷达”。
- 预期：检查原生 Livox topic、发布者和频率；频率 ≥ 2.0 Hz 为正常，0.5～2.0 Hz 为警告，低于 0.5 Hz 或没有原生 topic 为异常；仅存在派生点云不能判定原始雷达正常。

### ACT-NAV-010 单点导航发布顺序

- 优先级：P0
- 前置条件：定位状态为 ok，导航运行时 ready，B2 adapter 和 UDP 接收器 ready。
- 操作：在导航点列表点击“导航到该点”，核对坐标后点击“确认导航”。
- 实际发布顺序：

```text
/nav_task_start = false
准备 B2 运动模式并启动 cmd_vel_ros2_udp_sender.py
获取 NAVIGATION 控制权
发布 1 次：goal_yaw -> /clicked_point
```

- 预期：整个单点流程不发布 `/nav_start`；目标 frame 为 `map`，z 必须是导航点保存的显式、有限同层 ground 高度，缺失时拒绝请求而不是默认 0；新目标立即清除旧路径并显示 planning，收到 `/global_path` 后显示 path，`/nav/obstacle_status` 阻断时显示 blocked；旧任务不会继续执行；`/cmd_vel_safe` 经 UDP 只由 BotDog UnitreeB2Adapter 转发。

### ACT-NAV-011 单点到达判定

- 优先级：P0
- 类型：真机
- 操作：让机器狗实际走到目标点，持续观察 `/nav_status` 和 `/waypoint_status`。
- 预期：依次出现 accepted、moving、reached；单点必须同时满足 XY ≤ 0.12 m、Z ≤ 1.0 m、yaw 误差 ≤ 0.10 rad；后端映射为 navigating、navigating、reached；页面机器狗坐标、目标和路径一致。
- 注意：当前 `timeout_sec=0`，目标不会因耗时过长自动失败；测试时如出现持续不收敛，应人工点击“导航急停”。

## 8. 任务用例

### ACT-NAV-012 创建实际可执行任务

- 优先级：P0
- 操作：创建任务，绑定当前场景，只添加两个 `navigate_waypoint` 步骤 A、B，保存并刷新。
- 预期：任务写入 `data/nav_tasks/workflows.json`；ID、名称、场景和步骤顺序保持不变；空名称、空场景、空 waypoint 和未知步骤类型被拒绝。
- 限制：本轮实际执行测试不要添加姿态步骤，因为当前 ROS2 任务执行器不会执行姿态动作。

### ACT-NAV-013 执行多点任务

- 优先级：P0
- 操作：点击任务“执行”，检查 `data/nav_runtime/current_task.json` 和 topic。
- 实际顺序：先生成 `current_task.json`，再确认定位/导航 runtime、启动速度 sender、取得控制权，然后发布 `/nav_start=true`，最后发布 `/nav_task_start=true`。
- 文件预期：每个导航步骤包含 `waypoint_id/waypoint_name/x/y/z/ground_z/planner_goal_z/yaw/frame_id`；同时包含 `task_id/task_name/scene_id/scene_dir/map_pcd/ground_pcd/source_waypoints`。
- 执行预期：waypoint navigator 收到 `/nav_task_start=true` 时重新读取最新文件；到达 A 后自动发布 B；中间点只要求 XY/Z 到点，最终点还要求 yaw；全部到达后 `/nav_status` 报 reached 且 `task_complete=true`。
- 失败行为：收到 `/waypoint_reached=false` 时，当前点 1 s 后重试；当前没有最大重试次数。

### ACT-NAV-014 停止任务

- 优先级：P0
- 前置条件：任务正在执行。
- 操作：点击任务卡片或工具栏的“停止任务”。
- 预期：依次发布 `/nav_task_start=false`、`/nav_start=false`；停止 cmd_vel sender；释放 NAVIGATION 控制权；清空 global path 和 execution path；状态变为 idle；不会继续发布下一个任务点。

## 9. 状态、安全与异常用例

### ACT-NAV-015 状态和路径回传

- 优先级：P0
- 操作：正常导航并观察 WebSocket 页面；再分别发布合法和非法 `/nav_status` JSON。
- 预期：`accepted/moving/reached/failed/canceled/estop` 映射为 `navigating/navigating/reached/error/idle/estop`；失败消息和 error_code 保留；未知状态映射为 error；非法 JSON 只记 warning，不使 ROS bridge 退出；`/global_path` 和 `/scan/execution_path` 能显示并去重。

### ACT-NAV-016 导航软急停

- 优先级：P0
- 类型：真机安全
- 前置条件：先架空测试，再低速落地测试。
- 操作：运动中点击右侧“导航急停”。
- 预期：设置 cmd_vel estop；发布 `/nav_task_start=false` 和 `/nav_start=false`；向 `/cmd_vel` 连续发布 20 次全零 Twist，间隔 0.02 s；同时通过 BotDog 控制服务发送一次零速度；路径清空，状态变 idle。
- 关键预期：导航定位进程和 cmd_vel sender 保持运行，但之后的非零导航速度被 estop 门拒绝。再次点击“重启导航定位”会清除各层 estop 后重新进入重定位流程。

### ACT-NAV-017 速度单写入与看门狗

- 优先级：P0
- 操作：导航时观察 `/cmd_vel_safe`、UDP 入口和 B2；再停止发送 `/cmd_vel_safe`，切换手动控制、触发 E-STOP，并尝试发送非法 UDP 数据。
- 预期：只有控制权为 NAVIGATION 时有限、有效的本机 UDP 三个 double 才能转发；NaN、Inf、错误长度和非本机来源被拒绝；连续 0.5 s 未收到速度时只发送一次零速度；切换到手动控制后不发送延迟的导航 stop 干扰手动控制；E-STOP 使用 force stop。

### ACT-NAV-018 动态避障

- 优先级：P0
- 类型：真机安全
- 前置条件：`NAV_ENABLE_DYNAMIC_AVOIDANCE=true`，`/grid_map/occupancy_inflate`、TF 和路径均存在。
- 操作：导航时将软质障碍物放到前方 2 m 路径内，再逐渐移到 1.2 m 停车范围；保持障碍超过 2 s；随后移走障碍。
- 预期：只检查机器人前方 2.0 m 路径窗口；机器人自身 0.90 m 范围点被过滤；进入有效路径走廊的障碍将 `/nav/obstacle_status` 置为 blocked/caution；1.20 m 内 action=stop，`/cmd_vel_safe` 归零；持续 2.0 s 发布 `/nav/replan_request=true`；障碍清除后发布 false 并恢复 clear。
- 异常检查：障碍点云超过 1.5 s 未更新时状态为 sensor_lost 并输出零速度；TF 丢失时 waiting_tf 并输出零速度；机器人偏离当前路径超过 1.0 m 时 deviated 并输出零速度。

### ACT-NAV-019 刷新与重连

- 优先级：P1
- 操作：导航过程中刷新页面，再短暂断开并恢复浏览器网络。
- 预期：页面打开本身不重复发布导航目标；重连后通过 `/api/v1/nav/state` 恢复 robot pose、navigation status、localization status、global path 和 execution path；不会重复启动任务。

## 12. 立即停止测试的条件

- 存在两个能直接写入 B2 的控制进程。
