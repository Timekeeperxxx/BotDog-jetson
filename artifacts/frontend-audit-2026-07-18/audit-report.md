# BotDog 前端交付前审计

审计日期：2026-07-18

范围：登录页、主操作台、导航点云页、点云图层控制、后台总览、危险操作确认、390px 窄屏导航，以及构建、测试、依赖、浏览器控制台、可访问性和点云资源预算。

## 总体结论

桌面端的基础视觉和主要信息架构已经接近可交付，但当前不建议直接封版。至少应先处理移动端导航失效、关键流程缺少端到端回归，以及完整点云在 Jetson 上的真实内存/帧率验收。

## 交付前必须处理

### P0-1 移动端导航当前不可用

- 390×844 实测出现大面积重叠与裁切。
- 点云图层按钮坐标为 `(130,405)-(227,443)`，中心命中元素是场景信息里的 `Source`，不是按钮本身。
- 现有 760px 媒体查询只缩小部分宽高，没有重新组织登录条、场景信息抽屉、工具栏和弹层的层级。

建议：若交付明确只支持桌面，应在登录后明确阻止小屏并给出说明；否则需要为小屏设计单独布局，而不是继续压缩桌面布局。

### P0-2 关键控制流程缺少自动回归

- 49/49 单元测试通过，但全项目语句覆盖率仅 14.14%。
- `AppRoot`、`LoginPage`、`PcdMapDemoPage`、`PointCloud3DViewer`、`PointCloudTopDownCanvas`、`useNavScenes`、`useNavTasks` 等关键文件为 0%。
- 仓库没有正式 Playwright/E2E 套件。

建议至少补 5 条交付烟测：登录与会话过期、导航页加载、点云图层开关、任务开始/停止、危险操作只打开确认但不执行。

### P0-3 完整点云需要真机压力验收

- Scene35 最终精度：30,343,139 点、1,430 个节点、390,134,887 字节原始瓦片数据（约 372 MiB）。
- 当前要求是全部加载且不回收；浏览器同时保留 TypedArray 与 GPU buffer，点云本身可能接近或超过 744 MiB，尚未计入 HTTP 缓存、材质、Three.js、React、视频和系统开销。
- 1,430 个独立对象还会形成较多 draw call 和材质实例。

建议在目标 Jetson 上用实际 WebGL 和视频同时运行至少 30 分钟，记录浏览器 RSS、系统可用内存、FPS、点云完整加载时间与是否发生 GPU context lost。此项不能用无 GPU 的自动化截图替代。

## 建议在封版前处理

1. 视频错误态：将原始 404 改为“视频服务未就绪，正在自动重试”，显示下一次重试时间，并避免同一错误在三个位置重复出现。
2. 可访问性对比度：axe 检出登录页 1 个、主操作台 12 个、后台 39 个严重对比度节点，集中在 8–10px 灰色文字。
3. 模态框语义：统一 ConfirmDialog、ChangePasswordModal 等实现，补充 dialog 语义、标题关联、焦点锁定、Esc 与焦点恢复。
4. 全局错误兜底：当前没有应用级 ErrorBoundary，渲染异常可能直接白屏，且没有恢复入口。
5. 点数文案：把 3,993,965 标明为 `ground.pcd 点数`，同时显示完整场景最终点数 30,343,139，避免与加载进度冲突。
6. 后台健康提示：磁盘达到 88% 时应使用黄色/红色阈值提示，而不是与正常指标同等展示。

## 已确认的正向项

- 生产构建通过，ESLint 无业务代码错误。
- 49 个现有测试全部通过。
- `npm audit --omit=dev`：生产依赖 0 个已知漏洞。
- 登录页在桌面和 390px 下布局稳定。
- 桌面点云图层面板的名称、按下状态和分组基本清楚。

## 证据限制

- Playwright Headless Chromium 未提供可用 WebGL，因此没有把实际 3D 点云画面作为视觉验收证据。
- 当前机器人 TF、视频链路和部分服务处于等待/降级状态；审计没有发出机器人移动、导航、重启或删除命令。
- 截图与 axe 扫描不能证明完整 WCAG 合规，键盘焦点顺序和读屏器仍需人工复核。
